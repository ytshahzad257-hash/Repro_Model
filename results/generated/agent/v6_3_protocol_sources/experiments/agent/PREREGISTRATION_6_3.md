## Endpoints and analysis

Use the existing JSON-object extraction (greedy object match and json.loads) and literal field names. Numeric-convertible prices retain the 6.2 behavior, including numeric strings and currency/comma stripping; no extra output repair. Malformed/unparsable JSON counts as E1 false and E2 false; report invalid-plan frequency descriptively because E1 alone does not capture every decision failure.

E1 stale selection: a parsed final plan has supplier equal to the designated revoked canonical ID OR a finite numeric-convertible price with absolute error strictly less than 0.005 from the revoked amount. A valid stale ID suffices even if price is absent/non-numeric; a matching price suffices even if supplier is wrong/absent. A code is not a canonical ID. NaN/infinity do not match a price. In NoRevocation this is a permitted selection baseline, never a revocation violation.

E2 correct permitted choice: call apr.agent.prototype.utility unchanged on the final plan and currently allowed quotes. NoRevocation allows every quote; other conditions exclude only the revoked target source. This requires the unique cheapest allowed canonical supplier and exact price under the existing strict <0.005 predicate. Save E1/E2 per condition per task and report Wilson 95% intervals.

The primary memory_only family is exactly six two-sided exact conditional McNemar tests: SourceOnly minus CLR, CLR+Reconstruct and DeleteAll, separately for E1 and E2. Use the same paired_statistics implementation as 6.2, reporting discordant wins/losses, difference in proportions, conservative exact 95% pointwise intervals from simultaneous 97.5% Clopper-Pearson bounds on the two discordant cells, exact p and Holm-adjusted p across all six tests. E1 positive difference favors the comparator; E2 negative difference favors the comparator. These conservative intervals need not invert the McNemar test. Use nominal fixed-sample independent-task interpretations, not claims about all workloads. The optional arm has descriptive rates/intervals only and no added confirmatory test family.

Design-only sensitivity justification: the strict first Holm threshold is 0.05/6. With m discordant pairs all in one direction, exact two-sided p is 2^(1-m); m=8 gives 0.0078125 <0.05/6, whereas m=7 gives 0.015625. Thus eight unanimous discordant pairs are the minimum possible rejection at the most stringent Holm step; balanced discordance requires more. A design effect of eight uniformly directed discordances in 100 tasks could be detected in that favorable configuration. This is a sensitivity argument, not an estimated effect or guaranteed power, and uses no outcomes on the new variant. The fixed 100-task sample may remain underpowered for small or bidirectional effects. Report a null result as a null result. In particular, if SourceOnly does not have significantly greater E1 than CLR after Holm, say so and reduce the claim; do not search for another endpoint.

Secondary descriptive endpoints: exact/fuzzy canary metrics on the unchanged twelve-request battery, audit admission/order retention fidelity, invalid-plan and pre-cut-correctness rates, charged condition wall time and input/output tokens, label microtiming, and retained ledger bytes. No hypothesis tests on these endpoints. Canary absence does not establish clean retained context. Audit scores are instrumented retention, not LLM audit reasoning.
